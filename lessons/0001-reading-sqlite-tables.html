LESSON 01 · Quick reference

Read a table as a set of promises

Your goal: explain what these two tables permit, what they prevent, and what you would change for a different requirement. Start with bookmarks; notes repeats the pattern.

1. Read the three arguments

sqliteTable(
  "bookmarks",                 // SQL table name
  { /* column definitions */ }, // fields and column rules
  (table) => [ /* indexes */ ]   // table-wide configuration
)

export const bookmarks names the TypeScript value used by the application. Inside the columns, userId: integer("user_id") maps a JavaScript property to a SQL column name. The naming difference is intentional. Drizzle column documentation.

2. Translate each rule

CodeRead it as
id: integer("id").primaryKey({ autoIncrement: true })A numeric identifier for this row, generated when omitted.
userId: integer("user_id").notNull().references(() => users.id)A required user identifier that must reference an existing user when foreign keys are enabled.
lessonId with the same chainA required reference to an existing lesson.
createdAt: text(...).notNull().$defaultFn(...)A required text value; Drizzle supplies an ISO timestamp on insert when omitted.
uniqueIndex(...).on(table.userId, table.lessonId)The same user–lesson pair cannot appear twice.

The arrow () => users.id is a callback Drizzle uses to resolve the referenced column; SQLite receives a foreign-key declaration. This app enables enforcement in app/db/index.ts. SQLite foreign keys.

The central rule: user 7 may bookmark lessons 10 and 11; users 7 and 8 may both bookmark lesson 10. Only repeating the pair (7, 10) is forbidden. “Unique together” does not mean “each unique separately.”

3. Separate three places behavior can live

SQLite: enforces required values, references, and unique pairs in the generated migration drizzle/0012_colossal_maggott.sql.

Drizzle: $defaultFn runs in JavaScript. It creates no SQL default. A direct SQL insert must supply the required timestamp. See runtime defaults.

Application: app/lib/saved.server.ts trims notes, caps them at 2,000 characters, deletes a note when the trimmed body is empty, and explicitly sets updatedAt when saving. The schema alone does none of those things. NOT NULL permits an empty string.

4. Evaluate alternatives by the requirement

Current choiceWhen another choice helps
Separate id plus a unique pairA composite primary key on (userId, lessonId) could remove the explicit ID field. Useful when the pair is the identity; a separate ID remains convenient for references and deletes.
AUTOINCREMENTPlain INTEGER PRIMARY KEY also generates IDs. Prefer the stronger option when automatically reusing deleted IDs would be harmful; otherwise it adds bookkeeping. SQLite explains the difference.
Foreign keys with default NO ACTIONonDelete: "cascade" can remove dependent bookmarks and notes when a parent is deleted. Choose it only if that matches the desired data lifecycle. Deletion actions.
Application timestamp defaults and updatesA SQL default plus a database trigger can cover writers outside Drizzle. Explicit application timestamps are easy to control in tests; this service accepts a now argument.

My assessment: the pair constraint matches the service’s “one current note per user per lesson” behavior, including its conflict-update target. If the product needed multiple separate notes per lesson, that constraint would need reconsideration. These are requirement choices, not universal style rules.

5. Predict before revealing

Two note rows have different IDs but the same user and lesson. Will the second insert succeed?

Reveal feedback

No. Distinct primary keys do not bypass the unique constraint on the user–lesson pair.

You update only body through Drizzle. Does this schema automatically refresh updatedAt?

Reveal feedback

No. Its default supplies an insert value, not an update rule. The project’s save function explicitly supplies the new timestamp.

Primary reading: Drizzle’s SQLite columns, especially “Not null” and “Default value.” Ask your agent about any unclear line, or bring back your predictions to discuss them.
